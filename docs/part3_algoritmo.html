Como funciona o analyze_auth.sh

Os dados passam de cima para baixo. Os logs são lidos e ordenados uma vez, os eventos SSH são extraídos uma vez, e cada deteção só ordena esses eventos e passa por eles com a sua janela deslizante.

As três janelas deslizantes

Nas três deteções, o awk vê um grupo de cada vez (um IP ou um user) e os eventos já vêm por ordem cronológica. As falhas são numeradas k = 1, 2, 3… e o tempo de cada uma fica em t[k].

3.2 Brute force: N falhas seguidas cabem na janela?

exemplo: -b 4 -w 1
if (k >= n && t[k] - t[k - n + 1] <= window) detected = 1

Basta comparar a falha atual com a que está N−1 posições atrás. Uma janela fixa de 0 a 60 s só teria 3 falhas e deixaria escapar este ataque.

3.3 Password spray: quantos usernames diferentes há na janela?

-s 5, janela 60 min, média ≤ 3
rootaliceadmintestoraclefora da janela
while (t[k] - t[left] > window) { in_window[u[left]]--; if (in_window[u[left]] == 0) distinct--; left++ }
if (distinct >= n && (k - left + 1) <= max_avg * distinct) detected = 1

Aqui N conta usernames e não falhas, por isso a janela tem duas pontas. in_window[user] conta as tentativas de cada user dentro da janela, e distinct sobe quando um user entra e desce quando sai.

A janela só é calculada quando chega um sucesso, e as falhas ficam só guardadas. A mesma função corre duas vezes, agrupada por IP (coluna 1) e por user (coluna 4). Se as duas vias detetarem o mesmo login, a junção deixa uma só linha com o motivo both.
